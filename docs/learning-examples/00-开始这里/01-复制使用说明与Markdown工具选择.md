# 复制使用说明与 Markdown 工具选择

## 推荐结论

日常填写优先使用 **Obsidian 本身**。原因是内部链接、图片嵌入、属性、模板与正式 Vault 的目录结构都能原样预览；写完即可切回 Personal Learning，不需要在多个编辑器间同步。

| 工具 | 适合什么 | 不建议什么 |
|---|---|---|
| Obsidian | 日常复制模板、填写条目、插图、双链、复习 | 不擅长批量正则替换和复杂版本比较 |
| VS Code | 批量修改、多文件查找、检查 YAML/Markdown、处理 Git 项目 | 不要用它直接“美化”个人 Vault 后再盲目批量保存 |
| Typora | 专注写长文、预览表格和排版、导出阅读稿 | 不适合作为带 Obsidian 属性、Wiki 链接和插件字段的主编辑器 |

**建议组合：** Obsidian 负责正式写入；VS Code 只用于明确的批量技术维护；Typora 仅用于长文草稿或导出，不作为这个学习系统的必需工具。

## 从示范库进入 Personal Learning

推荐先按 [03-GAOKAO插件从零上手SOP](03-GAOKAO%E6%8F%92%E4%BB%B6%E4%BB%8E%E9%9B%B6%E4%B8%8A%E6%89%8BSOP.md) 使用插件创建笔记，让插件生成合法目录、稳定 ID 和基础字段：

1. 切换到 `GAOKAO-PERSONAL-LEARNING`。
2. 运行 `GAOKAO: Create subject learning note`。
3. 选择学科与模板，只填写标题，点击“创建并打开”。
4. 不知道正文如何组织时，再回示范库打开同科、同类型范例。
5. 复制十个固定正文区块并填写有依据的内容；不要复制示范 YAML、`gaokao_id`、事件、日期或图片路径。
6. 若使用 AI，先按图片范围筛选，再复制通用主 Prompt 及对应学科映射。
7. 对照教材、题目或批改结果人工复核，先校验结构；真实学习后才使用完成本轮或普通历史入口。

插件不可用时可以先保存无身份的正文草稿，但不能把它当成已入库 Entity 或手工建立第二套 ID 规则。恢复现有插件入口后再生成身份并校验。

## Markdown 套入建议

### 内部链接与图片

只链接本 Vault 实际存在的目标。新图附件路径和真实 SHA 由插件返回；完整原图嵌入与每图 SHA 一起放 Original Evidence，不能复制示例假路径、假题号或旧的“资源/附件”目录。纯文字无需图片。

### Callout 区块

```markdown
> [!important] 核心结论
> [待填写]

> [!warning] 易错边界
> [待填写]

> [!question] 主动回忆
> [待填写]
```

### 数学公式

行内公式使用 `$...$`，独立公式使用：

```markdown
$$
y=a(x-h)^2+k
$$
```

不要用图片代替可编辑公式；图片仅保留原题、图形、实验装置、批改证据等视觉信息。

## AI 输出写入前检查

- 是否把推测写成了事实？
- 是否漏掉定义域、实验条件、语境、对象或限定词？
- 公式、单位、箭头、上下标和正负号是否与原图一致？
- 图片中看不清的部分是否明确标为 `[无法辨认]`？
- 是否保留了你的原始错误与修正理由，而不只是抄标准答案？
- 是否生成了可复习的问题，而不是只有总结？

## 当前 R1–R5 复制规则

示例以“成品范例”中的正文为复制单位，文件名与一级标题一致；YAML 由插件生成，勿复制演示 ID、学习事件或排期。旧中文空白栏目已收敛到 [条目通用骨架](../%E6%A8%A1%E6%9D%BF/%E6%9D%A1%E7%9B%AE%E9%80%9A%E7%94%A8%E9%AA%A8%E6%9E%B6.md)。保留十区块，纯文字不伪造图片。按 [R1-R5写入规范](../%E6%8F%90%E7%A4%BA%E8%AF%8D/R1-R5%E5%86%99%E5%85%A5%E8%A7%84%E8%8C%83.md) 检查，Validate 不代替 R2/R3 结构检查。
