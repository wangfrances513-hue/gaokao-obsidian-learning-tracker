# GAOKAO 文字与图片入库：R1–R5 写入规范

适用：当前 v0.2；更新：2026-09-06。六科文字、照片、截图及混合输入共用本文。模板 ID、实体类型、默认目录由现有插件决定；正文格式与旧示例冲突时以本文为准。

## 图片与原件

- 精确识别本次指定的输入，不能改用旧附件。区分学习题图和软件报错截图；多张图按同题或多题的真实关系整理。
- 聊天附件有可读本地路径时，在已授权入库范围内精确复制到 `00-待处理` 并比较字节与 SHA；只在确实不可访问时请求补充。原件保留原路径，不自动删除、改名、移动或覆盖。
- 正式附件由现有入库功能创建或复用：`资源/图片/学科/YYYY/MM/实际SHA256.png`，JPEG 使用 `.jpg`。不编造路径或哈希，不创建第二套附件目录。
- 所有完整原图嵌入集中放入 `## Original Evidence`：`![[Vault相对路径]]`，下一段为 `SHA-256: 实际64位小写哈希`。每张图各对应自己的路径和 SHA。
- 当前 R1 直接按嵌入路径查文件，不加 `|宽度`、别名、`#锚点`、绝对路径或 `file://`。不用 HTML img、远程图片或普通 Markdown 图片语法替代受管嵌入。
- Source 只放来源、题号、页码或普通链接；图片链接可用 `[[资源/图片/...png]]`（没有 `!`），不能嵌图或泄露答案。
- Project 默认把全部图片放在 Original Evidence。Prompt 写可独立作答的无答案文字题面，保留必要条件、选项、图表数据与关系。纯图形题无法可靠转述时说明缺少可用的无答案题面，不能用占位句冒充就绪。
- 含解答、手写批改或无法确认无答案的图片不得放入默认展开的 Prompt。当前插件不会自动识别图片中的答案。
- 纯文字不伪造图片和 SHA；Original Evidence 可保留用户原文并说明来源，或留空。

## 固定正文

保留插件生成的 YAML，至少包含 `gaokao_id`、`entity_type`、`subject`，保留适用的关联和 review tag。新笔记不手写 sr-*；旧笔记整理保留其原值。

YAML 后只有一个 `# 标题`，必须与文件名去掉 `.md` 完全相同。一级标题后、首个二级标题前只允许空行。以下十个标题统一保留，各出现一次，使用精确英文名称：

|二级标题|用途|R2|R3|
|---|---|---|---|
|Source|现实来源或材料定位，无答案|展开|展开|
|Prompt|可独立作答的无答案题面／具体重建任务|展开|折叠|
|Cues|3–5 行短关键词列表|折叠|展开|
|Core Idea|核心概念、模型、识别信号|折叠|折叠|
|Error Boundaries|适用边界、易错点、用户实际卡点|折叠|折叠|
|Solution Skeleton|步骤骨架、决策顺序|折叠|折叠|
|Original Evidence|完整原图、实际 SHA、原作答或原文|折叠|折叠|
|Detailed Solution|详细解答、结果；区分 AI 推导与原始事实|折叠|折叠|
|Deep Dive|补充推导、分类讨论|折叠|折叠|
|Variant Pool|真实候选题定位或明确标注的自检建议|折叠|折叠|

当前解析器不接受额外中文二级标题、重复区块、三级及更深标题。学科特有内容用区块内 **加粗标签**、段落和列表保留。“识别信号”归 Core Idea，“标准方法”归 Detailed Solution，“决策顺序”归 Solution Skeleton，“分类讨论节点”归 Deep Dive，“易错点／当前卡点”归 Error Boundaries。

Cues 恰好 3–5 个非空列表行，每行 `- 关键词`，不超过 80 字符；不能夹入解释、图片、HTML 或最终答案。Source 与 Cues 避免 `<`、`>` 标记。Prompt 不使用代码围栏、HTML 或动态内容；行内公式与行内代码可用。

R1 可先确认已关联的材料；交付为“R2/R3 结构就绪”前必须实际填好 Source、Prompt、Cues。其余区块无内容时留空，不填 `...`、假路径、假题号、假错因。“无答案题面或现实作答任务”是写作提示，不能原样作为可复习题面。

## 生成骨架

以下是生成骨架，不是可直接提交的完成品；内容来自本次真实材料。

```markdown

## Prompt

## Cues

## Core Idea

## Error Boundaries

## Solution Skeleton

## Original Evidence

## Detailed Solution

## Deep Dive

## Variant Pool
```

## 执行与校验

1. 用户只要求预览时停在预览；明确要求写入、入库或修复时按已授权范围执行，不要求再次输入特定口令。仅询问影响学科、目标、关联身份或题意的实质歧义。
2. 图片复用既有 `GAOKAO: Capture image evidence`，纯文字复用既有创建笔记入口；身份、目录、关联与附件遵循插件。后续补写正文同样保持本规范。
3. 已授权旧笔记修复先备份再局部重排，保留有效内容、原图字节、SHA、gaokao_id、关联、sr-* 和历史。不得把原笔记替换为空模板。
4. 核对正式文件：身份唯一、来源实际存在、SHA 与图片字节一致、所有正文归入区块、Prompt 无答案且可作答、Cues 合规。
5. `Validate current note` 不替代 R2/R3 正文检查。具备环境时调用当前 `planRoundPresentation` 分别检查两轮，报告实际检查范围。原生首帧、窗口和进程恢复需要各自运行证据。
6. 学习材料入库不自动产生 Learning Event、评分或 scheduler 变化。不创建 round、stage、mastery、confidence、timer 或第二套状态库。
7. 报告实际路径、输入对应关系、校验结果及材料缺口。原件保留原路径，不自动移动到 `90-已处理`。

## R1–R5 接续

- 新 Entity 刷新 Today 后从 R1 材料确认开始；用户通过现有 Today／Record study/practice/verification 的“完成本轮”记录实际活动。普通历史记录不替代本轮完成。
- R2 展开 Identity、Source、Prompt；R3 展开 Identity、Source、Cues。图片与答案保留在折叠区；用户尝试后可以手动展开，折叠不改写 Markdown。
- R4 记录陌生同构题 practice；R5 记录现实验证 verification。同一次活动不得重复用于两个轮次。Project 可以整理题目和用户提供的过程描述，不能代造完成事件。
- 无评级按默认链推进；显式 Good/Easy 的快进由既有状态机处理，排期由 scheduler 写入。不要修改日期来让 Today 立即出现下一轮。
